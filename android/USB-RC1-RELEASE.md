# Android 0.3.0-rc1: повторная проверка USB

Исходный случай: iQOO владельца, Android API 36, Ch34xSerialDriver
1a86:7523, приложение 0.2.0-preview. Две попытки General завершились
таймаутом; третья получила только байт 10, без начального 51 и полного
пакета. Отдельная попытка вообще не обнаружила USB-кабель.

## Исправления

- Нативное чтение использует `UsbSerialPort.read(buffer, 0)` и размер
  USB endpoint вместо чтения по 512 байт с таймаутом 250 мс. В библиотеке
  3.11.0 это путь UsbRequest/requestWait; закрытие порта отменяет ожидание.
  Общий таймаут запроса протокола остаётся 5 секунд.
- Ошибка старого потока чтения не закрывает новое подключение.
- Заголовок, длина и checksum по-прежнему проверяются строго. Отсутствующий
  байт 51 не восстанавливается предположением; автоматического повтора
  записи нет. Пустые порции данных игнорируются до разбора кадра.
- UNEXPECTED_BLOCK/FRAME/WRITE_IO теперь сохраняются в истории; общий
  обработчик не дублирует одну и ту же ошибку в UART-журнале. В журнал
  добавлены версия приложения, API Android и драйвер USB без серийного номера.
- История показывает понятное имя блока и код 0x51 вместо непонятного «81».
  Уточнены сообщения об отсутствии USB и неполном ответе.
- targetSdk/compileSdk 36, обработчик системной кнопки «Назад» для новых
  Android; локальная подсказка о совместимости. Подпись и package ID сохранены
  для установки поверх 0.2.0-preview.

Это устранение найденного риска в чтении, а не доказанная причина потери
байтов на устройстве владельца. Питание мотора, разъёмы и OTG остаются
возможными факторами. Драйвер не заменён; DTR/RTS не переключаются наугад.

## Проверка

- Все 61 тест ядра, профилей, веб-приложения и JS-моста проходят. Шесть
  HTTP-тестов сначала упёрлись в sandbox EACCES на 127.0.0.1; повтор
  соответствующих файлов с разрешённым loopback — 8/8 успешно.
- Воспроизведение: отсутствие ответа и одиночный 10 закрывают сеанс и не
  разрешают запись; полный General с задержкой между частями принимается
  только после двух одинаковых чтений. Пустые порции не ломают разбор.
- assembleRelease, bundleRelease, assembleAndroidTest, testDebugUnitTest
  (2 теста), lintRelease: успешно. Lint: 0 ошибок, 5 предупреждений
  (версии зависимостей, feature-check и использование JavaScript в WebView).
- Подпись APK проверена; ключ совпадает с предыдущей preview.
- 44 браузерных сценария с Android-мостом: успешно, без ошибок JavaScript.
- Подписанный APK установлен поверх 0.2.0-preview на эмуляторе Android 15
  (API 35). Instrumentation проверяет запись истории на диск, повторное
  открытие, неудачные и прерванные сеансы, изоляцию снимков, лимиты и очистку.
  Эти тесты работают в отдельной папке и не удаляют пользовательскую историю.

SHA-256 APK: `142de1586b5bbfee2735ccba50ad38ade903b1b5b62484f0e5b0559bd0fcdd4e`.

Аппаратная проверка новой версии на iQOO ещё не выполнена. Публикация
Google Play не выполнена; универсальная совместимость не заявляется.

## Следующая проверка владельца

Установить 0.3.0-rc1 поверх старого приложения, не удаляя данные. Включить
OTG и питание мотора, подключить кабель, разрешить USB. Сначала выполнить
только «Подключить» и «Считать все блоки». При ошибке сохранить UART-журнал
и историю JSON; экспорт закрывает USB-подключение. До успешного полного
чтения и резервной копии запись остаётся заблокированной.

[CommonUsbSerialPort 3.11.0](https://github.com/mik3y/usb-serial-for-android/blob/3.11.0/usbSerialForAndroid/src/main/java/com/hoho/android/usbserial/driver/CommonUsbSerialPort.java)
и [Ch34xSerialDriver 3.11.0](https://github.com/mik3y/usb-serial-for-android/blob/3.11.0/usbSerialForAndroid/src/main/java/com/hoho/android/usbserial/driver/Ch34xSerialDriver.java).
